Plugin Importer Spec

The writing studio for Obsidian.

Binder, snapshots with side-by-side compare, inspector, corkboard, timeline, research, and compile. One plugin with switchable modules. Everything it adds is stored as Markdown, frontmatter, and git commits, so nothing needs Longhand to be read.

Write, snapshot, compare, restore.

Before a risky edit, take a snapshot and give it a name. That is one git commit for one file, and you never see git. When the edit goes wrong, open the Snapshots tab: only this document's named snapshots are listed, not every auto-commit in the vault. Compare shows the old version beside the live text with changes tinted at the word level. Pull back a sentence, or restore the whole thing. Restore snapshots the current state first, so nothing is ever the last copy.

If you are coming from Scrivener, the importer replays every snapshot you ever took as history with its original title and date. You arrive with your past intact.

Arrange a chapter by thread.

This is Scrivener's corkboard arranged by label, and it is the view writers miss most. One thread per label: a point-of-view character, a plot line, a location. The chapter's scenes run down the axis in manuscript order, each card sitting on the thread that matches its label. Drag a card up or down and the scene moves in the book. Drag it sideways and its label changes. The picture is the order of events and who carries them, at a glance.

Pin research to the scene that needs it.

Attach a PDF, an image, or a note to the document you are writing and it shows up beside the text whenever that document is open. Highlight a passage in the PDF and the highlight links back to the exact sentence it supports. Research lives in the vault as ordinary files; a pin is one line of frontmatter.

Mara found the letter in the tin with the buttons. The postmark was Whitby, the fourth of March, three days before the flood took the lower town.

She read it twice, standing, because sitting felt like agreeing to it.

  • PDF
    Whitby Gazette, March 1897
    Highlight, page 3: the water reached the chapel steps by nightfall
  • Harbour photograph, 1890s
    For the description of the quay
  • Postal routes, Yorkshire coast
    Your note. Confirms a three-day delivery.

See the book as cards.

The same cards, arranged another way. The corkboard makes an index card from each scene's synopsis, coloured by label. As a grid it is the chapter laid flat. As columns by status it is a kanban board. As threads by label it is the view above. Drag a card and the scene's order, status, or label changes in its frontmatter. There is nothing to keep in sync because there is only one copy.

Pin a scene to a place.

Any image can be a map: a hand-drawn world, a scanned town plan, a floor plan of the house. Drop a pin and link it to a scene, a character, or a note. Click the pin to open it; open the scene and see where it happens. Pins are stored on the map's own note, so the map is just a picture with frontmatter.

What changes in Obsidian

The file tree becomes a binder.
An ordered manuscript you drag to reorder. Folders are chapters, folder notes are chapter text.
The properties panel becomes an inspector.
Synopsis, label, status, notes, keywords, bookmarks, and attached research beside what you are writing.
Raw commits become named snapshots.
Per document, with compare and safe restore.
Three plugins become one board.
Grid, kanban columns, and label threads are arrangements of the same cards, reading the same synopsis, label, status, and date fields.
Research stays with the scene.
PDFs, images, and notes attached to the document you have open. Highlights link back.
Compile means a manuscript.
Presets for short story, novel, poem, essay. Docx, pdf, epub, or Markdown. Your files are untouched.
Any image becomes a map.
Pins link places to scenes and back. Stored as frontmatter on the map's note.
Every module has a switch.
One settings page. Turn off what you do not write with; nothing is stranded because every module reads the same fields.

Works with how you already sync

Longhand does not sync anything. Your vault keeps moving through iCloud, Dropbox, Obsidian Sync, Syncthing, or a git remote, whichever you use today. Snapshot history is stored as plain files inside the vault by default, so it travels with the vault to every device, including your phone. If you want real version control as well, turn on the git store: desktop only, and the repository is kept outside the synced folder so cloud sync never touches it.

Get it

Moving a project out of Scrivener

Our importer reads a .scriv package and writes a vault that follows the Longhand spec, snapshots included. The original project is never modified.

go install github.com/grassclaw/scrivener-to-obsidian/cmd/scriv2obsidian@latest
scriv2obsidian convert -out ~/Writing -git Novel.scriv

The plugin

In design and early development. The spec, the importer, the plugin core, and the Snapshots module are open source and will stay that way. Convenience modules may carry a licence later; nothing that guards your data ever will.

Follow the repo to hear when there is a build to try.
